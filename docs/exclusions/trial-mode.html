Trial / evaluation mode

Protects a deterministic subset of your project's eligible classes, so you can inspect real output before licensing the full build.

Implemented

What it does

Protects only a fraction of eligible classes instead of the whole JAR — selected by sorted internal class name, not at random, so the same input always produces the same trial output. Every unselected eligible class is written through completely unchanged, byte for byte. See Configuration for the flag.

Why a partial fraction, and why it's a parameter, not fixed

A trial has to do two things at once: prove the protection is genuinely real — a prospect opening the output in a decompiler needs to see actually renamed, encrypted, nativized classes with real cross-references between them, not one isolated toy example — while leaving the large majority of the actual codebase plainly readable, or there's no reason to buy a full licence. The exact fraction is exposed as a parameter rather than a hardcoded constant, since the right go-to-market percentage is a business decision, not an architectural one.

Verified. Run against a real, unmodified Apache Commons Exec build at a 20% fraction: the selected subset of classes protected and nativized correctly, and an unselected class confirmed byte-for-byte identical to the original input.
